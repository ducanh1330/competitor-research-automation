# workflows/

Markdown SOPs. Each file describes one repeatable job in plain language: what the
objective is, what inputs it needs, which tools to call in what order, what the
output looks like, and what to do when something breaks.

Workflows are **living documents** — update them when you learn a constraint
(rate limits, auth quirks, pagination behavior). Do not overwrite an existing
workflow without asking first.

Use `_TEMPLATE.md` as the starting point for a new one.
